Page 12 is about **getting information about files** using the `stat()` system call and the `struct stat`. Let’s go **deep, field by field**.

---

### `stat()` system call

- Purpose: Retrieve **metadata** about a file (not its content).
    
- Example:
    

```c
struct stat st;
stat("file.txt", &st);
```

After this, `st` contains all the information about `file.txt`.

---

### `struct stat`

This is the structure filled by `stat()`. Each field has a meaning:

|Field|Type|Meaning|
|---|---|---|
|`st_dev`|`dev_t`|Device ID containing the file. Helps OS know which disk or partition the file is on.|
|`st_ino`|`ino_t`|The inode number. Unique identifier for this file on the device.|
|`st_mode`|`mode_t`|Protection bits + file type (regular, directory, symlink, etc.).|
|`st_nlink`|`nlink_t`|Number of hard links pointing to this inode.|
|`st_uid`|`uid_t`|User ID of the file owner.|
|`st_gid`|`gid_t`|Group ID of the file owner.|
|`st_rdev`|`dev_t`|Device ID if this is a special device file (like `/dev/sda`).|
|`st_size`|`off_t`|Total size of the file in bytes.|
|`st_blksize`|`blksize_t`|Block size for filesystem I/O (useful for efficient reads/writes).|
|`st_blocks`|`blkcnt_t`|Number of blocks allocated on disk for the file.|
|`st_atime`|`time_t`|Last access time.|
|`st_mtime`|`time_t`|Last modification time (content change).|
|`st_ctime`|`time_t`|Last status change (like permissions, links).|

---

### Important concepts

1. **Inode-centered metadata:** Everything about the file (permissions, size, timestamps) is stored in the **inode**, not the filename.
    
2. **Hard links share inode:** Multiple filenames can point to the same inode. `st_nlink` counts how many.
    
3. **Different times:**
    
    - `st_atime`: last read
        
    - `st_mtime`: last content modification
        
    - `st_ctime`: last inode/status change
        

---

So, `stat()` gives a **snapshot of the file’s properties** at the OS level, without opening or reading the file itself.
