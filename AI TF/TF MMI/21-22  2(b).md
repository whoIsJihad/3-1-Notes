### 🧭 1. What is the **Travelling Salesman Problem (TSP)?**

The **TSP** asks:

> Given a list of cities and the distances between each pair,  
> find the **shortest possible route** that visits every city exactly once  
> and returns to the starting city.

Formally, if there are ( n ) cities:

- The solution is a **permutation** of the cities, like ( [A, B, D, C, A] ).
    
- The goal is to minimize the **total distance**:  
    $$
    \text{Cost}(P) = \sum_{i=1}^{n} d(P_i, P_{i+1})  
    $$  
    where ( d(i, j) ) is the distance between city ( i ) and city ( j ).

### ⚙️ 2. Why use a **Genetic Algorithm (GA)**?

[[Genetic Algorithm (GA)]] note can be found here 

TSP is **NP-hard**, meaning:

- Exact algorithms (like dynamic programming or brute-force search) become infeasible for large ( n ).
    
- GA provides a **heuristic** — a good (not guaranteed optimal) solution in reasonable time.
    

---

### 🧬 3. Genetic Algorithm Basics

A GA mimics **biological evolution**:

1. **Population:** A set of candidate solutions (chromosomes).
    
2. **Fitness:** A function that scores each candidate.
    
3. **Selection:** Choose the fittest candidates for reproduction.
    
4. **Crossover:** Combine two candidates to form a child.
    
5. **Mutation:** Randomly modify a candidate to keep diversity.
    
6. **Replacement:** Form a new generation, repeat until convergence.
    

---

### 🚗 4. Applying GA to TSP

Let’s tailor each GA step to the TSP:

#### 4.1 Representation (Chromosome)

Each chromosome = a permutation of cities.  
Example for 5 cities: `[A, C, E, B,  D]`.

#### 4.2 Fitness Function

We want **shorter tours → higher fitness**.

  
$\text{fitness}(P) = \frac{1}{\text{total distance}(P)}$  

(so shorter distance → higher fitness)

#### 4.3 Selection

Methods:

- **Roulette wheel selection** (probability proportional to fitness)
    
- **Tournament selection** (pick best from a random subset)
    

#### 4.4 Crossover (Recombination)

This is the trickiest part for TSP since order matters.  
Common operators:

- **Order Crossover (OX):** Keep a slice from parent1, fill the rest from parent2 keeping order.
    
- **Partially Mapped Crossover (PMX):** Map corresponding positions between parents.
    
- **Cycle Crossover (CX):** Preserves position relationships.
    

Example (OX):

```
Parent1: A B C D E F G
Parent2: D C F A G B E
Slice: [C D E]
Child:  _ _ C D E _ _
→ fill remaining from Parent2 in order: D C F A G B E → F A G B
→ Child = F A C D E G B
```

#### 4.5 Mutation

To avoid stagnation, slightly alter a chromosome:

- **Swap mutation:** Swap two cities.
    
- **Inversion mutation:** Reverse a segment.
    
- **Insertion mutation:** Take one city and insert it elsewhere.
    

#### 4.6 Replacement

Keep top individuals or use generational replacement.

---

### 🔁 5. GA Workflow Summary

1. **Initialize** population with random city orders.
    
2. **Evaluate** fitness for each route.
    
3. Repeat for each generation:
    
    - Select parents.
        
    - Apply crossover → offspring.
        
    - Mutate offspring.
        
    - Evaluate fitness.
        
    - Form new population.
        
4. Return best route found.

### 🧪 7. Optional Enhancements

- **Elitism:** Keep the best route in every generation.
    
- **Adaptive mutation rate:** Higher when population diversity is low.
    
- **Hybrid GA:** Combine with local search (e.g., 2-opt optimization).
