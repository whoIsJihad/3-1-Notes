## 2. Constraint Propagation: Arc-Consistency Algorithm (AC-3)

### 2.1. Discussion of Arc Consistency and AC-3

Arc consistency is a form of **local consistency checking** used to filter the domains of unassigned variables _before_ or _during_ the search process. A directed arc $(X_i, X_j)$ is **arc-consistent** if, for every value $x$ in the domain of $X_i$, there is some value $y$ in the domain of $X_j$ such that the assignment $\{X_i=x, X_j=y\}$ satisfies all binary constraints between $X_i$ and $X_j$.

The **AC-3 algorithm** iteratively enforces arc consistency across all the variables in the CSP until no more domain reductions can be made. It achieves this by maintaining a queue of arcs (or pairs of constrained variables) that need to be checked (revised).

**Process:**

1. Initialize a queue with all arcs $(X_i, X_j)$ for every binary constraint in the CSP.
    
2. While the queue is not empty, pop an arc $(X_i, X_j)$.
    
3. Call the `REVISE(X_i, X_j)` function.
    
4. If `REVISE` modifies the domain of $X_i$ (i.e., makes it smaller), then any _neighbor_ $X_k$ of $X_i$ (where $k \neq j$) might now be inconsistent with the reduced domain of $X_i$. Therefore, all arcs $(X_k, X_i)$ must be added back to the queue to be re-checked.
    

This process terminates when the queue is empty.

### 2.2. AC-3 Pseudocode

The algorithm is based on a core function, `REVISE`, and a loop that manages the queue:

```
// Main AC-3 Algorithm
function AC-3(csp):
    queue = a queue of all arcs (Xi, Xj) in csp
    while queue is not empty:
        (Xi, Xj) = POP(queue)
        if REVISE(csp, Xi, Xj):
            if size of Domain(Xi) is 0:
                return FAILURE // Inconsistent CSP
            for each Xk in Neighbors(Xi) where k != j:
                ADD(queue, (Xk, Xi)) // Add reverse arc for re-checking
    return SUCCESS // Arc consistency achieved

// Core Domain Reduction Function
function REVISE(csp, Xi, Xj):
    revised = false
    for each x in Domain(Xi):
        if there is NO y in Domain(Xj) such that (x, y) satisfies the constraint(Xi, Xj):
            DELETE x from Domain(Xi)
            revised = true
    return revised
```

### 2.3. Reducing the Time Requirement of AC-3

The initial complexity of AC-3 is $O(e \cdot d^3)$, where $e$ is the number of edges (constraints) and $d$ is the size of the largest domain. The primary way to reduce this time complexity, which leads to the $\mathbf{AC-4}$ and $\mathbf{AC-2001}$ algorithms, is to **avoid redundant re-checks** and **optimize the REVISE function**.

#### Method 1: Optimizing the REVISE Function (The AC-4/AC-2001 approach)

The $O(d^3)$ factor in `REVISE` comes from the inner loop: for every value $x$ in $D(X_i)$ ($d$ options), we must iterate over _all_ values $y$ in $D(X_j)$ ($d$ options) to check the constraint (potentially $d$ time for checking the constraint itself, or $O(1)$ for binary constraints).

To reduce the complexity of `REVISE` to $O(d^2)$:

- **Pre-calculate Support:** Instead of re-checking, pre-calculate how many values in $D(X_j)$ support each value in $D(X_i)$.
    
- **Maintain Counter:** For each pair of constrained values $(x, y)$, maintain a counter of the number of supporting pairs.
    
- **Lazy Deletion (AC-2001):** When a value $y \in D(X_j)$ is deleted, we only check the values $x \in D(X_i)$ that were _only_ supported by $y$. This is the basis of **AC-2001** (or AC-3.1), which uses a refined queue management system to achieve a better overall complexity of $O(e \cdot d^2)$.
    

#### Method 2: Improved Queue Management

In AC-3, when $D(X_i)$ is revised, we add **all** neighboring arcs $(X_k, X_i)$ back to the queue. This is often unnecessary.

- **Only Add Relevant Arcs:** We only need to add $(X_k, X_i)$ arcs where $X_k$ is a neighbor of $X_i$ that is constrained by $X_i$.
    
- **Prevent Duplicates:** Ensure the queue uses a set-like structure to avoid adding the same arc multiple times, which reduces redundant processing.
    

#### Method 3: Using a Domain Revision List (AC-2001)

AC-2001 uses an optimized method where the queue only holds variables whose domains have been revised, not the arcs themselves.

1. When $D(X_i)$ is revised, only $X_i$ is added to the list.
    
2. When processing $X_i$, the algorithm finds all neighbors $X_k$ and only checks arcs $(X_k, X_i)$ once.
    

This avoids the problem of adding potentially thousands of reverse arcs back into the queue and significantly improves the overall performance from a worst-case $O(e \cdot d^3)$ to $O(e \cdot d^2)$.
