# Greedy vs. A* Search: Utilizing Advantages and Avoiding Pitfalls

The following discussion addresses the advantages ("facilities") and disadvantages ("pitfalls") of the basic Greedy Search algorithm and describes the A* Search algorithm as a solution that leverages the strengths of the greedy approach while guaranteeing optimality.

## 1. Greedy Best-First Search

The **Greedy Best-First Search** algorithm is an informed search technique that expands the node closest to the goal, as estimated by a heuristic function, $h(n)$.

### (a) "Facilities" (Advantages) of the Greedy Algorithm

|Advantage|Description|
|---|---|
|**Simplicity**|The core logic is simple: always choose the neighbor with the lowest $h(n)$ value (best heuristic estimate).|
|**Efficiency (Time)**|Due to its aggressive nature, the Greedy Search often finds a solution **very quickly** by aggressively moving toward the goal. It explores far fewer nodes than an uninformed search like Breadth-First Search.|
|**Space Efficiency**|It typically requires less memory than algorithms like A* because it doesn't need to maintain or update the full path cost history.|

### (b) "Pitfalls" (Disadvantages) of the Greedy Algorithm

|Pitfall|Description|
|---|---|
|**Lack of Optimality**|This is the major drawback. Greedy Search is **not guaranteed to find the shortest or lowest-cost path** (the "optimality related problem"). It can get stuck following a path that looks good initially but turns out to be very expensive later.|
|**Completeness Risk**|It is not complete in all search spaces. It can enter an infinite loop if it encounters a cycle in the graph, as the heuristic cost may remain the same or appear to decrease within the cycle.|

## 2. A* Search: The Solution Algorithm

The **A* Search Algorithm** is the most widely used form of best-first search. It is designed to combine the time efficiency of the Greedy Search with the guaranteed optimality of Uniform-Cost Search.

### (a) How A* Utilizes Greedy "Facilities" and Avoids the Pitfall

A* utilizes the greedy approach by using the heuristic function $h(n)$, but it avoids the optimality pitfall by balancing the heuristic estimate with the actual cost incurred so far.

The core of A* is its **evaluation function,** $f(n)$:

$$f(n) = g(n) + h(n)$$

- $g(n)$ **(Actual Cost):** The cost of the path from the starting node to the current node $n$. This accounts for the **optimality** (ensures short paths are favored).
    
- $h(n)$ **(Heuristic Estimate):** The estimated cost of the path from the current node $n$ to the goal. This accounts for the **greedy efficiency** (ensures rapid progress toward the goal).
    

By summing these two components, A* ensures that it chooses the node that represents the **least estimated total cost** from start to finish.

### (b) A* Search Pseudocode

The A* algorithm uses an **OPEN list (or Priority Queue)**, ordered by $f(n)$, to manage the frontier of nodes to be expanded, and a **CLOSED list (or Set)** to store nodes already visited.

```
function A_STAR_SEARCH(start_node, goal_test):
    // 1. Initialize the Priority Queue (OPEN List)
    OPEN = PriorityQueue() // Stores (f(n), n) tuples, sorted by f(n)
    
    // 2. Initialize the start node costs
    start_node.g = 0
    start_node.h = HEURISTIC(start_node)
    start_node.f = start_node.g + start_node.h
    
    OPEN.INSERT(start_node)
    CLOSED = Set() // Stores visited nodes to avoid cycles and redundant work

    while not OPEN.IS_EMPTY():
        current_node = OPEN.EXTRACT_MIN()
        
        if current_node in CLOSED:
            continue
        
        CLOSED.ADD(current_node)

        // 3. Goal Test
        if GOAL_TEST(current_node):
            return ReconstructPath(current_node)

        // 4. Expand Node
        for each neighbor in GET_NEIGHBORS(current_node):
            // The cost to neighbor via current_node
            new_g = current_node.g + COST(current_node, neighbor)
            
            // If we found a better path to the neighbor
            if neighbor.g IS_INFINITE OR new_g < neighbor.g:
                neighbor.g = new_g
                neighbor.h = HEURISTIC(neighbor)
                neighbor.f = neighbor.g + neighbor.h
                neighbor.parent = current_node
                
                // 5. Update or Add to OPEN
                if neighbor is NOT in OPEN:
                    OPEN.INSERT(neighbor)
                else:
                    OPEN.UPDATE(neighbor) // Update priority if already present

    return FAILURE // Goal unreachable
```

### (c) Optimality Guarantee

A* guarantees finding the optimal (lowest-cost) path, provided two conditions are met:

1. **Admissibility:** The heuristic function $h(n)$ must **never overestimate** the cost to reach the goal (i.e., $h(n) \le h^*(n)$ for all $n$). This is crucial for _g(n)_ to always dominate.
    
2. **Consistency (Monotonicity):** The cost of getting from node $n$ to an adjacent node $n'$ must not decrease the heuristic estimate faster than the actual step cost (i.e., $h(n) \le COST(n, n') + h(n')$). This is required when $g(n)$ is fixed, ensuring that the $f$-cost of nodes along any path is non-decreasing.
    

By ensuring the heuristic is **admissible**, the search prioritizes nodes that lie on the optimal path, as non-optimal paths will eventually have a higher $f(n)$ value.
